## Findings (none caused a fail)

These are gaps in the skill text that the runs exposed. Each comes with the smallest change that would close it. `SKILL.md` has not been edited.

- **F1, REPAIR has no slot for its settings.** METHOD step 7 says to "Use low complexity unless the miss is layout", but the REPAIR output spec (line 54) allows only the misses and one fence, and line 30 says "Emit only the blocks for the active mode". As written, the user never sees the complexity choice. Proposed line 54:
  `REPAIR: at most 3 misses ranked by visual impact, then one fenced edit prompt for the top miss, then one SETTINGS line with its complexity and quality.`
- **F2, Text cut by the frame edge is ambiguous.** The rule on line 65 ("including any line that is only partly readable") could be read as banning crisp text that the crop cuts off. Eval 2's photo has such text ("KOS", "app for Claude AI"). The run transcribed it as visible glyphs, but another agent could drop it. Proposed addition after line 65:
  `- Text cut by the frame edge is not unreadable: transcribe the visible glyphs and state where the edge cuts them.`
- **F3, HARVEST's new-subject prompt has no SETTINGS.** Line 52 adds "one complete prompt" for a new subject, but no size or quality goes with it, so the user has to guess them. Proposed end of line 52:
  `If a new subject is named, add one complete prompt with its SETTINGS line.`
- **F4, "searched and found nothing" is not covered.** Line 13 covers "a search tool exists" and "no search tool", but not a search that finds nothing, which is what happened for gpt-image-3 today. The run did the sensible thing, but the text doesn't say so. Proposed line 13 ending:
  `...check its current limits when a search tool exists. If there is no search tool or the search finds nothing, say those limits are unverified and that SPEC values are used.`

Minor, no change proposed: line 12 ("Say so if you cannot [open it]") and line 27 (the exact sentence) agree for eval 7, because the exact sentence does say so.
